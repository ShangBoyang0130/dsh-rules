# 内容预检与会话手术

先看自己在哪个分支。

> **这份 skill 被两台机器各自维护过**，所以正文里凡是「另一份 / 工作区那份」的写法，
> 对**只装了这个包的人**都不成立 —— 那些句子已改成「**建议在工作区里也放一份**」。
> 只装包的人：`node <本 skill 目录>\preflight.js` 这一路照用，`surgery\` 就留在 skill 目录下。

## 分支一：还没读 —— 先预检（预防）

要读对话外的文本（网页抓取、日志、用户给的大文件）之前，把内容**落盘**，再预检：

```
node <本 skill 目录>\preflight.js <文件...>            预检这些文件拼起来的内容
node <本 skill 目录>\preflight.js --gap <文件> <a> <b>  二分出最小触发窗口，并用整份删除验证
```

- 退出码四态：`0` 通过｜`1` 被拦（内容审核）｜`2` 出错或参数不合法（**2 不是「被拦」**）｜
  `3` 只有 `--gap` 会返回：该窗口单独发就通过 ⇒ 缩窗口不适用（**3 也不是「被拦」**）
- ⚠️ **不是所有 400 都是内容审核**（2026-09-18 改）：参数写错、模型名不对、配额问题也会 400。
  脚本现在按错误码区分 —— 只有内容相关的码才返回 `1`（被拦），其余**返回 2 并把错误正文打出来**。
  看到 2 先照正文查参数/模型名/配额，**别急着做阅读包**。
- 200 才读。被拦就：`--gap` 量窗口 → 做「阅读包」（跳过窗口、其余片段拼成**新文件**）→ 逐次预检到 200 → 读那份包
- **200 只说明「这一次、这个形状」过了**：预检只发 1 条消息，真实请求还带系统提示、工具表、整段历史；
  实测同一段文本**差一个字符**就从 200 翻到 400。所以长材料**分批读**，单条工具结果别超过 8192 字符
- 用户**自己粘贴**的文本挡不住 —— 那种要在粘贴**之前**请用户先存成文件

## 分支二：已经死了 —— 做手术（救援）

症状：某一轮结束在 `Content Exists Risk`（HTTP 400），之后那个对话每轮都发不出去。

**死掉的对话自己用不了这个 skill**（它连一句话都发不出去），所以手术在**另一个活着的对话**里做：

```
node <脚本所在目录>\repair-session.cjs --session <会话id>            演练：只算不做
node <脚本所在目录>\repair-session.cjs --session <会话id> --apply    动真格：先备份再追加
```

- **建议在工作区里也放一份脚本**（比如 `<工作区>\活跃\内容预检\`）：`surgery\` 建在**脚本自己所在的
  目录**里，内容是 `plan-*`（剪过的正文）、`backup-*`（**整份会话日志**）、`surface-*`（重建的正文）
  —— **都含会话正文**。放工作区就落工作区；直接用 skill 目录那份，就落进 `~\.dsh\skills\`。
  （只装包、不在工作区另放一份也完全能用，只是产物落在 skill 目录里。）
- 原理：会话日志是只追加的，照 DSH 修剪器的做法补两条事件 —— `compaction/prune` 记账，
  加一条带 `surfaceOp:{op:"replace",startSeq,endSeq}` 与 `sourceEventSeqs` 的 `tool/result`，
  内容剪成「头 4096 + 标记 + 尾 1024」顶掉超长结果。**原文不删**，仍在日志里可回放
- **重启 dsh 时它会从日志重放** ⇒ 手术做完必须重启；停着做更保险，运行中做也成功过
- 回滚：备份在**脚本自己所在目录**下的 `surgery\`，覆盖回
  `~/.dsh\sessions\<工作区>\session-<id>\session.v3.jsonl.zstd`
- 核对（推荐）：`node <脚本所在目录>\verify-surgery.cjs <会话id> <备份路径>` ——
  查「只追加保证」（原文一个字节没动）、追加事件形状、被顶掉的原事件还在不在
- 写 `~/.dsh` 在工作区外，沙箱会拦 —— 按规矩把事和代价讲清楚，让用户授权
- `/compact` **不是救法**（实测：压缩请求自己也被拒），别在那儿花时间
- 更省事的一条（前提是进度一直落盘）：**换新会话**，读工作区的交接文件接上
  （这套体系的约定是 `活跃\交接.md`，见 `handoff` 那个 skill）

## 边界（照实说）

- 手术只在一个会话上做过（毒在超阈值工具结果里：11673 字符 → 剪成 5159）；
  毒在**用户消息**里、或毒在 **≤8192 字符的工具结果**里，没试过
- **DSH 重启时认不认追加的事件**：目前只做到静态核对（事件信封字段白名单、replace 必须正好三个键、
  `sourceEventSeqs` 非空无重复且涵盖被顶掉的表面节点 —— 三条都满足），**没有真重启验过**
- 预检只判「发得出去」，不判内容对不对
- Web 客户端没有 fork / rewind，「从带毒消息之前分叉」这条路不存在

## 换台电脑还能不能用（自查过 2026-09-16；安装与排障期才需要读）

- 三个脚本**不含任何本机路径**：会话目录靠扫 `~/.dsh\sessions\*\` 找（不写死工作区名）；
  会话目录名**两种形态都认**（`session-<uuid>` 与裸 `<uuid>`，实测两种都真实存在）；
  凭证按 `DEEPSEEK_API_KEY` → `~/.dsh\.credentials.yaml` 的顺序取。
- 可覆盖的环境变量：`PREFLIGHT_MODEL`（默认 `deepseek-flash`）、`DEEPSEEK_BASE_URL`、
  `DSH_CREDENTIALS`、`PREFLIGHT_TIMEOUT_MS`（默认 120000 ms）。
- 剪枝预算（头 4096 / 尾 1024 / 阈值 8192）取的是 DSH 修剪器的**默认值**；那边若改过配置，
  同步改 `repair-session.cjs` 顶部那三个常量。
- 依赖 Node 的 zstd 接口（**较新的 Node LTS 都带**；不确定就先跑一次演练，跑不起来它会直接报错）。
- **要整个目录一起拷**（手装时别只拷 `SKILL.md`）：这个 skill 带**三个脚本**
  （`preflight.js`、`repair-session.cjs`、`verify-surgery.cjs`），只拷说明文件的话它就是个空壳。
  用包里的 `install.ps1` 装不会有这个问题（它是**递归**整目录拷的）。
- **想在工作区里放一份也可以**（比如 `活跃\内容预检\`）：内容一样，好处是 `surgery\` 的产物落工作区。
  **用哪份都行，但别两边混着用** —— 产物会落在各自脚本的目录里。

# 盘我

对用户正在做的计划、决定或想法，做**一轮轮的追问**，直到设计树的每个分支都被解决。

这个 skill 只由用户手动触发 —— 不被要求就不来盘人。

## 它绕过的是什么

**人不知道自己漏了什么。** 知道的以为是显然的，所以不说；对方不知道，也不问 ——
沟通就断在这儿。

让 agent 来问，等于把负担搬到它最擅长的地方：从它的知识出发，列出「要做这件事需要知道
什么」，问出来的正好是用户没想到要说的那些。

## 方法：决策树 + 前沿 + 轮次

把这件事画成一棵**决策树**：每个决定分叉出挂在它下面的决定。

**前沿** = 前提已经定下来、现在就能问的那些问题，不用猜还没听到的答案。

一轮把**整个前沿**问完，然后**停下等回答**。回答会推动前沿外移，解锁原先问不了的问题。

一轮的写法：

```
❓ Q1 —— <问题标题>
   <问题正文，可以多段、可以带选项>
➡️ 推荐答案：<推荐怎么选，以及为什么>

❓ Q2 —— <同上>

（每题之间空一行）
```

**依赖另一个还没答的问题的那些，属于下一轮** —— 不要挤进这一轮。

## 两条分工

- **事实归 agent 查。** 需要环境里的事实（文件、配置、命令输出），自己去查，或者派 subagent
  去查 —— **不去问用户自己能查的东西**。查的同时**别阻塞**：只有依赖那个事实的问题等结果，
  前沿里其余的照问。
- **决定归用户。** 把每个决定摆到用户面前，然后**等他答**，不替他拍板。

（这跟 `AGENTS.md` 的「把选择权还给我」是同一条：agent 给天平，用户拨指针。）

## 三条边界（说清楚，别装作没有）

1. **问什么，上限是 agent 的领域知识。** 它不知道的坑，它问不出来 —— 它不会问 X，
   除非它知道 X 有影响。
2. **得先正确理解任务**，否则问的方向就偏。任务含糊时，第一个问题就是澄清任务本身。
3. **盘问有成本**（轮次、时间）。所以它由用户手动触发 —— 觉得「这事值得先对齐」时才付。

## 完成标准

**前沿空了**：设计树每个分支都走到，没有东西被默默假设。

到这儿停下，把结论总结一遍，**等用户确认「对齐了」再动手**。

## 收尾时做一件事

盘完之后，如果冒出了新词或新的固定说法，**问用户要不要收进术语表** ——
那份额外的共享词汇文件，见 `wait-what`。

# 交接

把这次对话压成一份文档，让**全新会话**里的 agent 能接着干。

存放位置：**本轮那条线**的目录下的 `交接.md`（通用线 / 规矩线 → 当前工作区的 `活跃\交接.md`），**固定这个文件名，每次覆盖**。

**哪条线？** 看工作区那份 `AGENTS.md`（用户的规矩文件）—— 有的工作区在里面列一张〈线清单〉表（每条线一行：目录 / 它的规矩 / **它的本轮状态**）；
线目录里那份 `AGENTS.md` 的路标里也写着本线的 `交接.md`。那儿没有你要写的那条线、或判断不了 → **问用户一句**
（宁可问，别写错那份：写错等于把这条线的状态写进别线，而两个会话读的是不同的文件）。

（放**工作区里**、而不是系统临时目录 —— 临时目录会被清理，交接就没了；固定名字也不会越攒越多。
**通用线**那份住 `活跃\`；**某条线**那份就住那条线的目录。`活跃\` 是这套体系的约定：
工作区下**在用的东西**放 `活跃\`、**做完归档的**放 `存放\`。
**没装过这个包的工作区**照这条约定自己建一个 `活跃\` 即可；用 `install.ps1` 装过的话，
它已经建好目录并放了一份空模板（含下面那张表的表头），直接改那份就行。）

## 写这几节

- **做到哪了** —— 现在的状态
- **下一步** —— 接着干什么，按顺序
- **已定的口径** —— **只列这一轮新定下的决定，并写清它们落在哪一份文件里**（口径文件 / 规矩文件 /
  代码 docstring）。⚠️ **别在交接里复述口径本身** —— 这份每轮被覆盖，复述一遍下一轮就没了；
  长期口径的家不在交接里（这条与全局规矩「别把长期口径写进交接」是同一条）
- **动过的文件** —— 一张表，表头固定三列 `| 位置 | 行数 | 是什么 |`；路径写带反引号的
  工作区相对路径（`活跃\x.md` 这种），行数按含空行算（`@(Get-Content <路径> -Encoding UTF8).Count`）。
  表后另起一行写「（行数一律 = `@(Get-Content <路径> -Encoding UTF8).Count`，含空行。）」——
  **如果你有核表的脚本**，让它靠这一行停表（作者那边是这么用的；没有脚本也不影响这份交接可读）。
  **格式与列名以本条线上一次的交接文件为准：先读它，别自己另起一套**（这条线第一次写，就照
  工作区里已有的任一份）。
- **还没做的 / 存疑的** —— 明确写出来，跟已完成的分开

## 两条硬要求

1. **只引路径，不复述内容。** 已经写进文件的（规矩文件、skill、说明），给路径让下一个 agent
   自己去读 —— 复述等于造两份会各自过期的副本。
2. **脱敏。** 不写 API key、密码、个人信息；涉及就写「见某路径」，不抄内容。

## 指明下一步要谁动手

单独一节，写清哪些 skill 需要**用户手动调用**：

```
下一步：用户需要打 /agents-md-audit 来审规矩文件
（这类 skill 对模型不可见，只有 `/` 能调用）
```

**不要写成「调用 skill 工具」** —— 对模型不可见的 skill，那样写会失败；要写成给用户的动作。

## 如果 `/handoff` 后面跟了文字

把那句话当成「下一个会话要干什么」的说明，按它裁剪文档重点。

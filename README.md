# dsh-rules

> **这个包不含 dsh 本身** —— 它只装规矩和 skill。
> dsh 请另外装：`npm i -g @deepseek-ai/dsh`（需要先有 Node.js）
一套给 **DeepSeek Harness（`@deepseek-ai/dsh`）** 用的**工作规矩 + skill**。

它不是"提示词大全"，是一套**能长期维护的规矩体系**：哪些东西每轮都在花上下文、哪些按需加载、
怎么防止规则越加越多最后反而失效。设计原则来自
[mattpocock/skills](https://github.com/mattpocock/skills) 里的 `writing-for-agents`，
加上维护者自己的实测。

---

## 30 秒装法

**前提**：这台机器上已经装好了 Node.js 和 dsh。没装的话，先跑
`winget install OpenJS.NodeJS.LTS`，再跑 `npm i -g @deepseek-ai/dsh`。

**下载**：[最新发布版](https://github.com/ShangBoyang0130/dsh-rules/releases/latest)（点开选 **Source code (zip)**），
或者右上角绿色 **Code → Download ZIP**。区别只有一条：发布版钉在某个标签上、内容不会变；
Code 那份跟着 `main` 走 —— 所以没发新 release 的时候，Code 那份可能比发布版新。

1. 解压下载到的 zip
2. **双击 `安装.bat`**
3. 按提示填工作区目录（直接回车就用默认的）
4. 装完之后：**关掉正在跑的 dsh**，双击 `<工作区>\活跃\启动dsh.bat`
5. **打开 dsh 的网页界面，在最下面的输入框里打一个 `/`**

看到 **7 个** skill，就是装好了。下面都是"想知道更多时再看"。

> **关于工具：这个包只提醒，不替你装。** 装它本身只需要 **Node.js + dsh**，别的都不用。
> 以后你做的事可能会用到别的命令行工具 —— 常见的是 **Python**（数据处理）、
> **PowerShell 7**（`pwsh`，跨平台的脚本）、**git**（版本管理）。用到了再说，
> **装不装、装哪个版本由你决定**；规矩不会替你装东西，也不会把安装步骤当成流程的一部分。

## 装不上 / 不对，先看这里

| 症状 | 原因和办法 |
|---|---|
| 双击 `install.ps1` 一闪而过，或报 **"禁止运行脚本"** | Windows 默认禁止跑 `.ps1`。**双击 `安装.bat` 就好** —— 它已经绕开了这一条。要坚持自己跑 PowerShell 的话，用：<br>`powershell -ExecutionPolicy Bypass -File install.ps1` |
| 装到一半报**找不到包里的某个文件**（名字是中文） | 解压工具没认出 zip 里的中文文件名。换一个解压工具重新解压（或从 GitHub 重新下载）。<br>脚本现在会在开跑前先确认源文件在，报出来的就是缺的那一个 —— 看到这句不是你的错 |
| 提示**找不到 `dsh`** | 先装 Node.js，再 `npm i -g @deepseek-ai/dsh`，然后**重开一个 PowerShell**。<br>重开还是没有 → 跑 `npm ls -g` 看有没有 `@deepseek-ai/dsh`。**没有就说明当初是用 `npx` 跑的** —— `npx` 只把包临时下载跑一次，不算安装，也不会留下 `dsh` 命令 |
| 界面显示 **401 未授权** | 第一次必须用**带 token 的地址**进：打开 `<工作区>\_dsh-web.log`，**在里面找 `http://127.0.0.1:3080/?token=…` 这一段**（整行前面还有 `dsh web: ` 这类前缀，别连前缀一起复制），粘到浏览器。<br>进去一次就种下 cookie，之后不带 token 的裸地址也正常。**启动脚本打开的正是裸地址，所以第一次一定会撞 401**。<br>⚠️ 这个日志**每次启动都被覆盖重写**，token 也是**每次启动新生成的** —— 换一次启动就拿新日志里那一段。 |
| 第一次启动**特别慢**（几十秒） | 正常，而且只有第一次。首启要做两件一次性的事：profile 从模板初始化、杀毒把两万多个文件扫一遍。<br>**判断办法：再启动两三次看那个秒数** —— 掉到十几秒就是好了，不用优化 |
| 打 `/` 里**没有 skill** | dsh 服务要重启一次才会刷新菜单（新建 skill 后菜单不会自动更新） |
| 打 `/` 里**有，但点了没反应** | 那个 skill 的文件位置变过。重启 dsh 服务即可 |

## 装什么

| 装到 | 内容 |
|---|---|
| `~/.dsh/AGENTS.md` | 全局规矩 —— 每个会话都会自动读 |
| `~/.dsh/术语表.md` | 统一用词，两边用同一批词 |
| `~/.dsh/skills/<文件夹名>/SKILL.md` | **7 个** skill（整目录拷，有的带脚本） |
| `~/.dsh/skills/说明.txt` | 那个目录的说明（加新 skill 的规矩、文件夹名 vs 菜单名的区别） |
| `<工作区>/AGENTS.md` | 工作区说明（说清这个文件夹是干什么的） |
| `<工作区>/活跃/`、`<工作区>/存放/`、`<工作区>/_tmp/` | 骨架目录（只建目录，不动里面已有的东西） |
| `<工作区>/活跃/交接.md`、`待办.md`、`归档索引.md` | **三份空模板**，说明这三份文件是干什么的。⚠️ **只在还没有这份文件时才装** —— 你已经写过内容的话，安装脚本一个字都不碰 |
| `<工作区>/活跃/启动dsh.bat` | 一键启动脚本（里面的工作区路径已填成你选的） |

上面这些**规矩文件、skill、启动脚本**：已存在的会**先备份成 `.bak.<时间戳>`**，不会静默覆盖；
**那三份模板反过来** —— 已经存在的**直接跳过**（它们是你自己的活文档，覆盖等于把你的内容清空）。

**两份文件是按原作者的情况写的**：`术语表.md` 的**第一组**是这套体系自己的说法，不用改；
**第二组「技术词」是按原作者还在学的词列的**，换个人就按自己的进度增删。
`AGENTS.md` 里的「跟我合作的规矩」同理 —— 那是原作者自己的偏好，别人用之前先改成自己的。

## 已经装过旧版：怎么更新

**步骤跟第一次装一样**：下载新版 → 双击 `安装.bat` → 重启 dsh。只有一处要当心：
**工作区必须填原来那个** —— 安装脚本提示时直接回车，会用默认的 `%USERPROFILE%\dsh-workspace`；
原来的工作区在别处的话，新版会装进一个新工作区，旧的那份一点不动，结果是半新半旧。

覆盖的就是上面「装什么」列的那些文件，每个覆盖前都备份成 `<名字>.bak.<时间戳>`；
想退回旧版，用备份盖回去就行。**只有那三份模板例外**（`交接.md` / `待办.md` / `归档索引.md`）：
它们装过一次之后就归你了 —— 再装时脚本**直接跳过**，不会碰你写的内容。

⚠️ **如果你的 `<工作区>\AGENTS.md` 被你自己改过**（加过路标、私有约定），更新时它会被
**新版覆盖**（旧的那份留在 `AGENTS.md.bak.<时间戳>`）。**合并的办法**：先把新版那份读一遍
（它带一段通用路标），再把你自己的内容贴回去 —— 直接拿备份盖回去会把新增的路标丢掉。

## 7 个 skill

| 显示名 | 怎么触发 | 干什么 |
|---|---|---|
| `agents-md-audit` | **你打 `/`** | 用一轮检查项 + 交叉验证过一遍规矩文件（几条以那个 skill 里的清单为准） |
| `writing-for-agents` | **模型自己会调** | 写 skill、改规矩文件之前的规则 |
| `content-preflight` | **模型自己会调** | 把大段外部文本读进上下文之前 / 会话被内容审核退回之后 |
| `exploration-outsourcing` | **模型自己会调** | 派子会话去读、去搜、去核之前 |
| `grill-me` | **你打 `/`** | 让 agent 反过来一轮轮追问，直到没有默认假设 |
| `handoff` | **你打 `/`** | 把当前会话压成交接文档，下一个会话接着干 |
| `wait-what` | **你打 `/`** | 没听懂时喊停，让它带着缺的上下文重讲 |

**菜单里显示的是 SKILL.md 里 `name` 字段的值（只能小写英文 + 连字符），文件夹名是中文 —— 两个不一样。**
文件夹名只影响你在资源管理器里看到什么，改它不会改菜单。
（`name` 写成中文不是"菜单里显示中文"，而是这个 skill 会被**整份忽略、从菜单里消失**，而且不报错。）

**哪三个是"模型自己会调"的**（`writing-for-agents`、`content-preflight`、`exploration-outsourcing`）
—— 它们都是「**agent 必须在某个时刻自己想到去调用**」的那种：写文档前、读大材料前、
以及手上探索变重该往外分的时候。其余四个做成"只由你手动触发"：它们**零上下文成本**，
代价是**你得当那个索引**。这也正是 `/` 菜单存在的意义。

## 装完之后，这套体系长什么样

这套规矩的核心是**一种分工**：每轮都读的东西尽量少，**其余按需读**。
下面的目录树是 **`install.ps1` 装出来的那一种分法**（在用的 / 归档的分开）——
**它是一份约定，不是硬要求**：换成你自己的分法也行，把工作区 `AGENTS.md` 里的路标一起改掉就成。
装完你手上会有这些：

```
~\.dsh\
  AGENTS.md          ← 全局规矩：每个会话自动读（跨项目，跟具体项目无关）
  术语表.md          ← 统一用词
  skills\            ← 7 个 skill：打 / 才用到，或者模型自己判断该用时才读

<工作区>\
  AGENTS.md          ← 工作区说明：说清这个文件夹是干什么的（也可以放自己的路标）
  AGENTS.local.md    ← （可选，要自己建）不想公开的私有补充；DSH 会自动一起读
  活跃\              ← 在用的东西
    交接.md          ← 本轮状态：下一个会话靠它接手，每轮覆盖
    待办.md          ← 要干的活：开工先读它
    归档索引.md      ← 位置台账：哪份产物在哪、退路在哪（平时不打开）
  存放\              ← 做完归档的，按成品对待
  _tmp\              ← 临时产物（脚本输出、一次性报告）
```

**为什么这么分**（这是这套东西唯一需要理解的一件事）：

- **寿命不同就别住一起**：每轮都变的（交接、待办）和几乎不变的（长期口径、位置台账）
  混在一个文件里，前者会不停地改后者，而且**改完的条目删没删没有任何东西看得见**
- **读法不同就别住一起**：开工读待办、接手读交接、找退路翻索引 —— 一份文件只服务一个时刻
- **规矩只写「会让人做错事」的**：违反它不会丢东西、不会算错、当场就能发现的，那是提醒，
  不必写成条款（这条判据在全局规矩里，叫「三问筛选」）

**用起来是什么感觉**：平时正常说话就行，全局规矩自动生效；想起来了就打 `/` 叫一个 skill。
第一份交接可以照 `活跃\交接.md` 那份模板写 —— 它把格式和三条硬规矩都写好了。

## 这套东西的设计原则

- **两种成本要分开算**：常驻上下文（每轮都花）vs 你的记忆负担。**第二种不该清零** ——
  它是"人还在决策"的代价，该花在值得你判断的地方
- **invocation 判定**：只有 agent 必须自己够到、或别的 skill 必须够到时，才让模型看见它；
  否则做成"仅限用户"，零上下文成本
- **说正面目标**：写"不要 X"会把 X 拉进上下文，反而让它更可得（"别想大象"）。说出要做什么
- **优先砍，不优先加**：一份只增不减的文档会**沉积** —— 旧条款一层层沉下去，
  最后要钻穿才能找到还活着的那些

## 怎么改（这部分是给「维护自己的人」看的）

**你拿到的这份就是正本** —— 想改哪条规矩、哪个 skill，直接改，没有"重新生成"这一步。
下面说的「源 / 派生 / 重新生成」只在**原作者**那边成立（他要把同一批文件同步到多台机器、
并生成这个公开包）；**你不需要 `maintainer\` 里的任何东西**，那些脚本也不在包里。

**如果你确实动了包里的东西**，注意两类文件的分工（原作者那边也按这条分）：

| 类 | 有哪些 | 改完要做什么 |
|---|---|---|
| **派生件**（从源拷过来的） | `rules\`、`skills\`、`launcher\` | 原作者那边要跑 `maintainer\build.ps1` 重新生成；**你直接改就行** |
| **包自有件**（手写的，没有源） | `README.md`、`install.ps1`、`安装.bat`、`templates\`、`maintainer\` | 直接改。⚠️ **`templates\` 不属于「重新生成」的范围** —— 改了它不会被任何构建覆盖，也不会被覆盖回来 |

**包里的 skill 数（7）比源里的少** —— 原作者那边有一份 `$ExcludeSkills` 清单，
列着「**本机专属、不收进包**」的 skill：它们带着那台机器的绝对路径、依赖那台机器的数据，
交出去也只是个壳。他加一个本机专属 skill 时要往清单里补一行，否则那次构建会以退出码 1 停下
（**这是故意的**：宁可挡住，也不要漏出去）。**你这边不用管这条。**

下面这段是**原作者**的日常动作，贴在这儿只是为了让包的生成过程可追溯：

```powershell
# 改完源之后，重新生成 rules\ 、skills\ 、launcher\
.\maintainer\build.ps1 -Workspace D:\我的工作区

# 提交、推送（第一次会顺手把仓库建出来）
.\maintainer\发布.ps1 -Repo dsh-rules
```

`build.ps1` 生成完会做四道机检，任何一道不过就退出 1：**痕迹检查**（出现本机用户名、
用户目录、或这次构建用的工作区路径就失败）、**BOM 检查**（会被 PowerShell 执行的 `.ps1`
必须是 UTF-8 带 BOM，否则中文会被按 ANSI 读、脚本跑到一半才炸）、**泄露探测**
（拿工作区里的私有词清单扫派生件与本包自有件）、**一致性比对**（`-Check` 时用）。

它还会把工作区 `AGENTS.md` 里**用 `<!--本机专属-->` … `<!--/本机专属-->` 圈住的内容删掉**
再放进包：本机自己的东西（本地主线路标、检查脚本路径这类）圈起来，就只留在本机。
发布件因此仍然是「从源派生的」，不用另维护一份模板 —— 代价是**新加的本机专属内容得自己记得圈**
（圈与不圈都写在同一行里：整行圈发布件里整行删掉，只圈一句就只删那一句）。

**泄露探测**用的是工作区里的 `活跃\本机词清单.txt`（一行一个词，`#` 开头与空行不看，
这份清单不进包）：扫派生件**和**包自有件（含 `templates\`），命中就构建失败。
清单不在就跳过这一步 —— 只装来用的人不会有这份清单。
**三道管的是不同东西**：痕迹检查管用户名与路径，BOM 检查管「脚本在 5.1 上跑不跑得起来」，
泄露探测管本机自己的项目名。

`发布.ps1` 需要先装好 `git` 和 `gh`，并跑过一次 `gh auth login`。凭据那一步刻意留给人：
脚本只调用**已经登录过的** `gh`，自己不经手任何令牌。

## 可选的 `.local` 覆盖层（2026-09-15 实测）

DSH 除了每层目录的 `AGENTS.md` / `CLAUDE.md`，还会自动加载**同目录**的
**`AGENTS.local.md`** / `CLAUDE.local.md`（越具体越优先）。

用途：把**私有补充**（本机路径、个人偏好、不想公开的东西）放进 `<工作区>\AGENTS.local.md`，
不必污染要公开的 `AGENTS.md`；归档 / 推送时把它排除即可。

**注意**：全局份**没有** `.local` 变体 —— `~/.dsh/` 下只认 `AGENTS.md` 一个名字
（来源：`@deepseek-ai/dsh-agent-instructions` 里 `USER_GLOBAL_FILE = "AGENTS.md"`），
所以本机专属的东西不要写进全局份，否则一公开就带出去。

**加载顺序与预算**（同一次实测，读的是 `@deepseek-ai/dsh-agent-instructions` 的源码）：

- 从**项目根一路到当前目录**，每层都找 `AGENTS.md` / `CLAUDE.md`，再加上它们的 `.local` 覆盖层；
  **越具体越优先**（同目录的 `.local` 盖过 base）
- **没有 include / import 机制**：想让内容自动进上下文，就必须真写在这些文件里；
  只放一句「见 XXX」＝ agent 得自己去读一次（省不了那份上下文）
- 有**字节预算**，超了会截断并打一行 `Workspace instruction budget N bytes` 提示

## 注意（都是实测踩过的）

- **`SKILL.md` 这个文件名不能改** —— 改了 skill 会彻底消失，而且不报错
- 文件夹名随便取（中文也行）。身份来自 `SKILL.md` 里的 `name` 字段，那个必须是 kebab-case
- **仓库里的 `.ps1` 必须存成 UTF-8 带 BOM** —— Windows PowerShell 5.1 否则会把中文读成 ANSI、
  脚本直接解析失败
- 新建 skill 之后，**`/` 菜单要重启 dsh 服务**才看得到（模型目录是当场生效的）

## 这个仓库是怎么来的

**人和 AI 一起做的。** 方向和每一次拍板由维护者出；调研、写作、代码、反复核对由 dsh 里的
agent 出。过程中双方都拦下过对方的错。

所以它既是一份能用的工具，也是一份"这样用 AI 能得到什么"的记录。

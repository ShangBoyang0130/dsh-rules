# dsh-rules

> **这个包不含 dsh 本身** —— 它只装规矩和 skill。
> dsh 请另外装：`npm i -g @deepseek-ai/dsh`（需要先有 Node.js）

一套给 **DeepSeek Harness（`@deepseek-ai/dsh`）** 用的**工作规矩 + skill**。

它不是"提示词大全"，是一套**能长期维护的规矩体系**：哪些东西每轮都在花上下文、哪些按需加载、
怎么防止规则越加越多最后反而失效。设计原则来自
[mattpocock/skills](https://github.com/mattpocock/skills) 里的 `writing-for-agents`，
加上维护者自己的实测。

---

## 30 秒装法

**前提**：这台机器上已经装好了 Node.js 和 dsh。没装的话，先跑
`winget install OpenJS.NodeJS.LTS`，再跑 `npm i -g @deepseek-ai/dsh`。

1. 把本仓库下载下来：右上角绿色 **Code → Download ZIP**，解压
2. **双击 `安装.bat`**
3. 按提示填工作区目录（直接回车就用默认的）
4. 装完之后：**关掉正在跑的 dsh**，双击 `<工作区>\活跃\启动dsh.bat`
5. **打开 dsh 的网页界面，在最下面的输入框里打一个 `/`**

看到 5 个 skill，就是装好了。下面都是"想知道更多时再看"。

## 怎么确认装好了

| 检查 | 应该看到 |
|---|---|
| 在 dsh 的输入框打 `/` | 5 个：规矩审查 / 重讲 / 盘我 / 交接 / 给AI写文档 |
| `~\.dsh\AGENTS.md` | 存在（全局规矩） |
| `~\.dsh\skills\` | 5 个文件夹 + 一个 `说明.txt` |
| `<工作区>\AGENTS.md` | 存在（工作区说明） |

## 第一次用：马上能试的三件事

| 想干什么 | 怎么做 |
|---|---|
| 刚才那段没听懂 | 打 `/重讲` |
| 有个决定拿不准，想被反过来盘问一遍 | 打 `/盘我` |
| 这轮差不多了，想让下个会话接着干 | 打 `/交接` |

**你不需要"运行"这些 skill** —— 平时正常说话就行，全局规矩会自动生效。skill 只在你要用它的时候，
从 `/` 菜单里叫出来。

## 装不上 / 不对，先看这里

| 症状 | 原因和办法 |
|---|---|
| 双击 `install.ps1` 一闪而过，或报 **"禁止运行脚本"** | Windows 默认禁止跑 `.ps1`。**双击 `安装.bat` 就好** —— 它已经绕开了这一条。要坚持自己跑 PowerShell 的话，用：<br>`powershell -ExecutionPolicy Bypass -File install.ps1` |
| 提示**找不到 `dsh`** | 先装 Node.js，再 `npm i -g @deepseek-ai/dsh`，然后**重开一个 PowerShell** |
| 打 `/` 里**没有 skill** | dsh 服务要重启一次才会刷新菜单（新建 skill 后菜单不会自动更新） |
| 打 `/` 里**有，但点了没反应** | 那个 skill 的文件位置变过。重启 dsh 服务即可 |

## 装什么

| 装到 | 内容 |
|---|---|
| `~/.dsh/AGENTS.md` | 全局规矩 —— 每个会话都会自动读 |
| `~/.dsh/术语表.md` | 统一用词，两边用同一批词 |
| `~/.dsh/skills/<文件夹名>/SKILL.md` | 5 个 skill |
| `<工作区>/AGENTS.md` | 工作区说明（说清这个文件夹是干什么的） |
| `<工作区>/活跃/启动dsh.bat` | 一键启动脚本 |

已存在的文件会**先备份成 `.bak.<时间戳>`**，不会静默覆盖。

## 5 个 skill

| 显示名 | 怎么触发 | 干什么 |
|---|---|---|
| `agents-md-audit` | **你打 `/`** | 六项检查 + 交叉验证，过一遍规矩文件 |
| `writing-for-agents` | **模型自己会调** | 写 skill、改规矩文件之前的规则 |
| `grill-me` | **你打 `/`** | 让 agent 反过来一轮轮追问，直到没有默认假设 |
| `handoff` | **你打 `/`** | 把当前会话压成交接文档，下一个会话接着干 |
| `wait-what` | **你打 `/`** | 没听懂时喊停，让它带着缺的上下文重讲 |

**只有 `writing-for-agents` 是"模型自己会调"的** —— 因为写文档时，agent 必须自己想到去用它。
其余四个做成"只由你手动触发"：它们**零上下文成本**，代价是**你得当那个索引**。
这也正是 `/` 菜单存在的意义。

## 这套东西的设计原则

- **两种成本要分开算**：常驻上下文（每轮都花）vs 你的记忆负担。**第二种不该清零** ——
  它是"人还在决策"的代价，该花在值得你判断的地方
- **invocation 判定**：只有 agent 必须自己够到、或别的 skill 必须够到时，才让模型看见它；
  否则做成"仅限用户"，零上下文成本
- **说正面目标**：写"不要 X"会把 X 拉进上下文，反而让它更可得（"别想大象"）。说出要做什么
- **优先砍，不优先加**：一份只增不减的文档会**沉积** —— 旧条款一层层沉下去，
  最后要钻穿才能找到还活着的那些

## 怎么改（维护者看这一节）

**源在你自己的 `~/.dsh/` 里**（`AGENTS.md`、`术语表.md`、`skills/`）。

这份仓库是**生成出来的产物，不是第二份真话源** —— 改完源，重新生成即可。
所以你可以把它当构建产物：随便删、随便重生成。

维护者工具都收在 `maintainer\` 里 —— **只装来用的人不需要碰它们**：

```powershell
# 改完源之后，重新生成 rules\ 、skills\ 、launcher\
.\maintainer\build.ps1 -Workspace D:\我的工作区

# 提交、推送（第一次会顺手把仓库建出来）
.\maintainer\发布.ps1 -Repo dsh-rules
```

`build.ps1` 生成完会**自动做一遍痕迹检查**：产物里一旦出现本机用户名、具体用户目录、
或这次构建用的那条工作区路径，构建直接失败 —— 免得把带痕迹的包推上去。

`发布.ps1` 需要先装好 `git` 和 `gh`，并跑过一次 `gh auth login`。凭据那一步刻意留给人：
脚本只调用**已经登录过的** `gh`，自己不经手任何令牌。

## 注意（都是实测踩过的）

- **`SKILL.md` 这个文件名不能改** —— 改了 skill 会彻底消失，而且不报错
- 文件夹名随便取（中文也行）。身份来自 `SKILL.md` 里的 `name` 字段，那个必须是 kebab-case
- **仓库里的 `.ps1` 必须存成 UTF-8 带 BOM** —— Windows PowerShell 5.1 否则会把中文读成 ANSI、
  脚本直接解析失败
- 新建 skill 之后，**`/` 菜单要重启 dsh 服务**才看得到（模型目录是当场生效的）

## 这个仓库是怎么来的

**人和 AI 一起做的。** 方向和每一次拍板由维护者出；调研、写作、代码、反复核对由 dsh 里的
agent 出。过程中双方都拦下过对方的错。

所以它既是一份能用的工具，也是一份"这样用 AI 能得到什么"的记录。
